# Fluffnest — арт-пайплайн и стайлгайд v0.1

> Документ для того, кто генерирует арт в Krea, и для Claude Code, который принимает ассеты в движок.
> Главная цель: каждый ассет встаёт в игру без доработки кода — питомцы органично живут в комнатах, мебель встаёт в слоты.

---

## 1. Стиль

**Описание:** kawaii-чиби стикеры, мягкая акварель + гуашь, пастель, тонкий тёплый коричневый контур, огромные блестящие тёмные глаза с белыми бликами, розовый румянец, очень круглые мягкие формы.

**Палитра**

| Роль | Hex |
|---|---|
| Фон / сливки | `#FFF8F0` |
| Румяный розовый | `#F9C5D1` |
| Мята | `#BFE8D6` |
| Лаванда | `#D9CCF2` |
| Сливочное масло | `#FBE7A1` |
| Небесный | `#BFDDF5` |
| Контур | `#6B4A3A` |
| Текст UI | `#5A4038` |

**Пропорции по стадиям** (голова : тело)

| Стадия | Пропорция | Силуэт |
|---|---|---|
| Новорождённый | один комок, голова = тело | шарик, глаза полуприкрыты |
| Кроха | 1.3 : 1 | голова больше тела, коротенькие лапки |
| Подросток | 1.1 : 1 | вытягивается, хвост и уши выразительнее |
| Взрослый | 0.9 : 1 | всё ещё чиби, пушистее, «достоинство» |

Окрас, пятна и отличительные метки сохраняются на всех стадиях — питомец узнаваем.

---

## 2. Перспектива и свет (общие для всех ассетов)
- Фронтальный вид с лёгким наклоном сверху ~10–15°. Без изометрии и без сильного 3/4.
- Свет мягкий сверху-слева, тени лёгкие внутри формы.
- **На спрайтах нет теней на полу** — их рисует код.
- **Нет запечённых эффектов:** искр, сердечек, звёздочек вокруг объекта — это частицы движка.

---

## 3. Питомцы

### 3.1 Model sheet вида (для утверждения)
5 стадий в ряд, в нейтральных позах, на одной ровной линии пола, без предметов.

### 3.2 Production-спрайт стадии
- **Одна нейтральная поза:** сидит или стоит на ровной поверхности, корпус развёрнут чуть вправо, взгляд в камеру.
- Влево питомец смотрит через отражение по X, поэтому асимметричные пятна допустимы, но надписей и «левосторонних» деталей быть не должно.
- **Запрещено** (правило самодостаточной позы, SPEC §7.7):
  - предметы в лапах или во рту (еда, игрушки, цветы в лапах);
  - позы, которым нужна опора или окружение: лёжа на облаке, сидя в чашке, в коробке, на луне, в прыжке;
  - аксессуары, впаянные в персонажа (бантики, капюшоны, венки) — это отдельные слои аксессуаров;
  - обрезанные части тела, текст, рамки.
- Позы «внутри предмета» рисуются отдельно как спрайт интеракции, вместе с предметом (§4.3).

### 3.3 Нарезка на части (для рига)
Минимальный набор частей на стадию 2–5:

| Часть | Комментарий |
|---|---|
| `body` | дорисовано под головой и лапами (нет дыр при повороте) |
| `head` | без глаз, рта и румянца |
| `ear_l`, `ear_r` | пивот у основания |
| `tail` | пивот у основания |
| `paw_fl`, `paw_fr` | передние лапки |
| `feet` | задние лапки (можно одной частью) |
| `eyes_*` | набор выражений, §3.4 |
| `mouth_*` | набор выражений, §3.4 |
| `blush` | отдельный слой, альфа регулируется кодом |

- **Перекрытие 10–15%** в местах сочленений (основания ушей, шея, лапки) — чтобы при вращении не появлялись щели.
- Яйцо: `shell_bottom`, `shell_top`, `crack_1..3` (оверлеи), `peek_eyes` (глазки в трещине).

### 3.4 Выражения
- Глаза: `open`, `closed`, `happy` (^ ^), `sad`, `surprised`, `love`, `sleepy`.
- Рот: `closed`, `smile`, `open`, `chew`, `wavy`.
- Каждое выражение — отдельный PNG того же размера и с той же позицией, что и `open` / `closed`.

### 3.5 Технические требования
- PNG с прозрачным фоном, sRGB.
- Мастер: кадр 1024×1024 на стадию (взрослый занимает ~85% высоты), экспорт @2x и @1x.
- Поля ≥ 32 px вокруг персонажа.
- В `rig.json` указываются `groundY` (линия контакта с полом) и пивоты.

## 4. Мебель и предметы

### 4.1 Общие правила
- Тот же фронтальный ракурс, свет сверху-слева, без теней на полу.
- **Пивот = центр контакта с полом** (середина нижнего края).
- Габаритные классы (логические юниты комнаты 1000×700):
  - `floor_small` — до 160×160;
  - `floor_large` — до 320×280;
  - `wall` — до 200×200;
  - `ceiling` — до 240×160.
- Тиры 1–3: тот же силуэт и габарит, растёт детализация и декор (тир 3 — «вау»).

### 4.2 Контейнеры (чашка, коробка, корзина, кроватка, луна)
- Два слоя: `back` (сам предмет) и `front` (только передний край / бортик).
- Питомец рисуется между ними — так он оказывается «внутри».
- Генерировать передний край отдельно или вырезать его из полного спрайта.

### 4.3 Спрайты интеракций (bound poses)
- Позы «спит в чашке», «сидит в коробке» — это клипы рига, использующие те же части питомца. По возможности отдельный арт не нужен.
- Если поза принципиально новая (свернулся клубком), генерируется отдельный набор частей `pose_curled` для каждой стадии; он используется только внутри interaction point.
- В `item.json` отмечаются `interactionPoints` (SPEC §6.4) — позиция, куда встаёт `groundY` питомца.

### 4.4 Аксессуары
- Рисуются на прозрачном фоне в той же перспективе, без персонажа.
- В `accessory.json`: якорь (`head_top` / `neck` / `face` / `back`) и точка крепления на спрайте.

## 5. Комнаты
- **Пустые шаблоны:** текстура стены (тайлится по X), текстура пола, плинтус, срез здания (боковые стенки-«разрез», балка перекрытия).
- **Никакой** мебели, окон, ламп, растений, персонажей.
- Пол виден полосой глубиной ~18% высоты комнаты (SPEC §7.2).
- Темы MVP: «Тёплое молоко» (кремово-персиковая), «Мятный сад» (мята + светлое дерево). Позже: «Лавандовая ночь», «Клубничное печенье».
- Внешний вид башни (крыша, фасад, небо день/ночь) — отдельные спрайты.

## 6. Workflow в Krea

1. **Style anchor.** Загрузить референс-мудборд в Krea. Отобрать 3–5 утверждённых концептов, передавать их как image-референсы в каждую генерацию. Когда наберётся ~20 утверждённых ассетов, обучить на них собственный стиль (Krea Styles / LoRA) для консистентности.
2. **Model sheet вида** — Nano Banana Pro (21:9, 2K).
3. **Production-поза стадии** — edit-модель (Nano Banana Pro / GPT Image / Seedream 5.5) с model sheet в референсе: «same character, stage N, neutral sitting pose, body slightly turned right, plain white background, no props, no accessories, no shadow».
4. **Прозрачный фон** — модели с поддержкой прозрачности (GPT Image 2.6 Flare, Qwen Image 2.1) или удаление фона.
5. **Разбор на слои** — Seedream 5.5 Layerize как черновик, затем ручная доработка в Krita/Photoshop: разделить части, дорисовать перекрытия. Альтернатива — генерировать «exploded parts sheet» (части персонажа отдельно на листе). Закладывать время на ручную чистку: ИИ-нарезка редко бывает идеальной.
6. **Выражения** — edit-модель от production-позы: «same image, change only the eyes to closed happy arcs», затем вырезать только глаза/рот.
7. **Мебель** — сначала лист из 6–9 предметов для выбора направления, затем каждый предмет отдельно на прозрачном фоне; для контейнеров — отдельный передний край.
8. **Проверка в движке** — положить файлы в `assets/`, открыть превью ассета в debug-панели: пивот, линия земли, слои, отражение.


## 9. Чеклист приёмки ассета
- [ ] Перспектива фронтальная, свет сверху-слева.
- [ ] Прозрачный фон, нет теней на полу, нет запечённых эффектов и текста.
- [ ] Питомец: нейтральная самодостаточная поза, лапки пустые, нет аксессуаров.
- [ ] Части нарезаны, перекрытия на сочленениях, пивоты и `groundY` указаны.
- [ ] Все выражения совпадают по размеру и позиции.
- [ ] Мебель: пивот в центре контакта с полом, габарит соответствует классу слота.
- [ ] Контейнеры разделены на `back` и `front`.
- [ ] Комната пустая.
- [ ] Ассет проверен в debug-превью движка.
